## 2. Toolchain & Lockfile Analysis

### Finding ID: CYPHER-SEC-012
### Title: Cargo Lockfile Version 4 Toolchain Incompatibility
- **Severity**: Informational
- **Affected File**: `Cargo.lock`
- **Original Issue**:
  `Cargo.lock` was committed using Cargo lockfile format `version = 4` (generated by Rust 1.78+ / 1.80+), which cannot be parsed by Rust toolchains <= 1.75.0 (`lock file version 4 was found, but this version of Cargo does not understand this lock file`).
- **Root Cause**:
  Recent Rust editions (1.78+) default to lockfile format v4, encoding dependencies as `"package version"` strings.
- **Implemented Solution**:
  Documented minimum compiler requirements in `README.md` and CI workflows (`dtolnay/rust-toolchain@stable` pinning to recent stable compiler).
- **Status**: Documented

## 3. Dependency Security Evaluation

### Core Dependencies:
- `anchor-lang = { version = "0.31.1", features = ["init-if-needed"] }`
- `anchor-spl = "0.31.1"`
- `solana-program = "1.18.26"` (transitive through anchor)

### Security Features & Profiles:
In `Cargo.toml`:
```toml
[profile.release]
overflow-checks = true
lto = "fat"
codegen-units = 1

[profile.test]
overflow-checks = true
```
- **Overflow Checks**: `overflow-checks = true` is explicitly enabled in release and test profiles, providing Defense-in-Depth against arithmetic wraps even in optimized SBF bytecode.
- **LTO**: Link-Time Optimization (`lto = "fat"`) and single codegen unit (`codegen-units = 1`) minimize binary size and eliminate dead code.
- **Unsafe Code**: Codebase audit confirmed `#![forbid(unsafe_code)]` compliance — zero `unsafe` blocks exist across all contract source files.
